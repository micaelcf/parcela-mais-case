# Verification — pre-approval-journey

Read by the lead and the Stage 5 auditor. Never split per slice.

## Swept

- identifier exposure: public responses and SSE snapshots C98, C99; storage C100; logs C54; backoffice lists carry no CPF C112, the CPF is only in the detail C113 and never in a URL C153; abuse view shows patient id + first name and 8-hex IP hashes C115; audit records name the operator username, not a patient C110. Error payloads: C3 pins the `fields[{ path, message }]` shape, but no check proves a 422 never echoes the submitted value (see Coverage, Unproven)
- input validation at the surface: create body C41–C43, scenario gate C49, requote preconditions C90, choose ownership C74, CPF search C114, list query allow-lists C6, C117, production-mode mapping C3. Kill-switch body `{ enabled }`: positive path only (C109)
- authorization: every `/api/backoffice/*` route except login sits behind the auth plugin, proven as a table over every route C103. Public consultation routes are capability URLs by design (RFC D13): no auth, no PII (C98, C99)
- transaction and atomicity: create = one TX including the pg-boss sends via `fromDrizzle(tx)` (contract `boundaries.md`); replay yields one fan-out C46; a `PATIENT_LIMIT` rollback leaves no consultation C93; settle + consultation settle + `pg_notify` in one TX, so NOTIFY fires only after commit C63; choose locks the consultation row C75
- idempotency and retry: create C46/C47, requote C91, choose C73, finalize is idempotent and runs both as a job and lazily on read C52/C61. Lender jobs have `retryLimit: 0` (RFC D10); exactly one call per attempt C51
- concurrency and ordering: finalizer vs late worker C52, concurrent chooses C75, single half-open probe under an advisory lock C57. Concurrent creates for one CPF racing the patient cap are serialised by `SELECT … FOR UPDATE` on the patient row, but no check races them (see Coverage, Unproven)
- failure modes and the error contract: every `api.md` error code has a proof (Coverage row "error codes")
- external dependency failure: lender 500 C35/C51, lender timeout C36/C50, unreachable or garbled lender `INTEGRATION_ERROR` distinct from `LENDER_ERROR` C37, repeated failures open the breaker C56. Postgres unreachable: `doctor` reports it C82; `/api/health` deliberately reports process liveness + SHA only (C4), not DB health
- data lifecycle: `request_throttle` purge C96; `lender_setting` seeded by migration C11; offers have no update/delete path (`schema.md`). Patient upsert overwrites `full_name`, `birthdate`, `phone` with the newest submission while each consultation keeps its frozen inputs C48. Not in scope: retention/deletion of patient PII; the PRD sets no retention period (raised for the audit)
- state transitions: attempt `PENDING` → exactly one terminal state, later results discarded C52; consultation `QUOTING` → `SETTLED` C50/C61; choice null → one offer, never changed C74/C75/C76; lender enabled ⇄ disabled C109. `journeyStatus` is derived, not stored C65
- generated code and schema provenance: migrations only from `drizzle-kit generate`, tree clean after C10; `src/routeTree.gen.ts` regenerated by the router plugin and excluded from fmt/lint (S0); `src/components/ui/**` only from the shadcn CLI (S8)
- audit trail and observability: kill-switch changes append-only with actor and time C110; one PII-free JSON line per lender call C54; `chosen_at`, `settled_at`, per-attempt `picked_at`/`called_at`/`settled_at` timestamps C113
- public interface documentation: no OpenAPI artifact exists in this repo. The contract is `export type App` (Eden) plus `contract/api.md`; shape changes amend `api.md` and the RFC in place (Stage 4 rule)
